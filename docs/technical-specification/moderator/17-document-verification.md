## 17. Проверка документов преподавателей и верификация

### 17.1. Назначение

Процесс описывает загрузку преподавателем документов (паспорт, диплом, сертификаты и т.п.), их проверку модератором платформы и принятие решения о верификации. Верификация подтверждает личность, образование и достижения преподавателя. После положительного решения в профиле преподавателя появляются соответствующие отметки. Документы хранятся ограниченное время и затем автоматически удаляются.

### 17.2. Участники, пред- и постусловия

**Участники:**

- преподаватель (загружает документы);
- модератор платформы с правом `verify_tutor_documents` (проверяет документы, принимает решение);
- администратор (при необходимости управляет правами модераторов, продлевает сроки хранения);
- система (хранит документы, отправляет уведомления, управляет сроками хранения, обновляет статусы верификации).

**Предусловия:**

- преподаватель авторизован и не забанен (`users.is_banned = false`; статус учётной записи может быть любым, кроме заблокированного);
- у преподавателя существует профиль (`tutor_profiles`) — необязательно публичный;
- существует хотя бы один модератор с правом `verify_tutor_documents`;
- преподаватель загрузил хотя бы один документ соответствующего типа.

**Постусловия (успешное завершение при одобрении):**

- документ помечен как проверенный (`status = 'approved'`);
- в профиле преподавателя появляются соответствующие отметки: «Личность подтверждена» (для паспорта), «Образование подтверждено» (для диплома), «Сертификат подтверждён» (для каждого сертификата);
- преподаватель получает уведомление об успешной проверке.

**Постусловия (при отклонении):**

- документ помечен как отклонённый (`status = 'rejected'`);
- преподаватель получает уведомление с причиной;
- существующие верификации по этому типу, как правило, сохраняются, но модератор может принять решение об их отзыве (см. 17.6 п. 8 и открытый вопрос №72).

**Постусловия (по истечении срока хранения):**

- файлы документов удаляются из хранилища;
- запись о документе удаляется или помечается удалённой;
- верификационные записи в `tutor_verifications` сохраняются (если документ был одобрен).

### 17.3. Входные данные

**При загрузке документа (преподаватель):**

| Поле                       | Обязательность                      | Валидация                                          |
| -------------------------- | ----------------------------------- | -------------------------------------------------- |
| Тип документа              | обязательно                         | `passport`, `diploma`, `certificate`               |
| Название (для сертификата) | обязательно, если тип `certificate` | до 200 символов                                    |
| Файл(ы) изображения        | обязательно                         | jpg/png/pdf, до 10 МБ каждый, проверка содержимого |

Для одного документа может быть загружено несколько файлов.

**При решении модератора:**

| Поле                               | Обязательность                                    | Валидация                           |
| ---------------------------------- | ------------------------------------------------- | ----------------------------------- |
| Решение                            | обязательно                                       | `approve` или `reject`              |
| Комментарий                        | обязателен при `reject`, опционален при `approve` | до 1000 символов                    |
| Отозвать существующую верификацию? | опционально при `reject`                          | булево значение; по умолчанию false |

### 17.4. Основной процесс

**Загрузка документов преподавателем:**

1. Преподаватель в личном кабинете открывает раздел «Верификация» или «Документы».
2. Выбирает тип документа (паспорт, диплом, сертификат).
3. При необходимости указывает название (для сертификата).
4. Загружает файлы (по одному или несколько).
5. Нажимает «Отправить на проверку».
6. Сервер сохраняет запись о документе в таблице `verification_documents` со статусом `pending`, сохраняет файлы в защищённое хранилище, связывает их с записью.
7. Сервер отправляет уведомление модераторам с правом `verify_tutor_documents` о новом документе.

**Проверка документа модератором:**

1. Модератор получает уведомление о новом документе.
2. Открывает карточку преподавателя и просматривает загруженные документы.
3. Сверяет данные: соответствие документа указанному типу, читаемость, подлинность (насколько можно судить визуально), отсутствие расхождений с данными профиля.
4. Если всё корректно — нажимает «Согласовано» (approve). Если есть проблемы — нажимает «Отклонить» (reject) и указывает причину. При отклонении модератор может отдельно указать, нужно ли отозвать существующую верификацию по этому типу (если она была ранее).
5. Сервер создаёт запись о решении (связь с документом, модератор, время, комментарий).
6. При approve:
   - Статус документа меняется на `approved`.
   - В таблице `tutor_verifications` создаётся запись (или обновляется, если уже была) с типом документа, временем верификации и ссылкой на документ. Для паспорта — «личность подтверждена», для диплома — «образование подтверждено», для сертификата — отдельная запись с названием сертификата.
   - Преподаватель получает уведомление «Документ проверен, верификация пройдена».
7. При reject:
   - Статус документа меняется на `rejected`.
   - Если модератор указал «отозвать верификацию», соответствующая запись в `tutor_verifications` удаляется (или помечается недействительной). Если не указал — верификация сохраняется.
   - Преподаватель получает уведомление с причиной отклонения.

**Автоматическое удаление документов:**

1. Для каждого документа при вынесении решения устанавливается поле `expires_at = reviewed_at + срок хранения` (по умолчанию 30 дней).
2. По истечении срока система (фоновая задача) удаляет файлы из хранилища и запись о документе из БД (или помечает удалённой).
3. Верификационные записи в `tutor_verifications` сохраняются.

**Повторная верификация:**

1. Если потребовалась повторная проверка, модератор пишет преподавателю в личные сообщения на платформе с просьбой повторно отправить документы.
2. Преподаватель загружает новые документы, процесс повторяется.

### 17.5. Ошибочные и альтернативные ветки

1. **Документ нечитаем или не соответствует типу.**  
   Модератор отклоняет с комментарием, преподаватель получает уведомление.

2. **Преподаватель загрузил несколько файлов для одного документа, но часть нечитаема.**  
   Модератор может отклонить весь документ или запросить замену отдельных файлов через личные сообщения (без формального отклонения) — на усмотрение модератора. В системе поддерживается только approve/reject.

3. **Нет модераторов с правом `verify_tutor_documents`.**  
   Заявка остаётся в очереди, уведомление не отправляется. Администратор должен назначить права.

4. **Срок хранения истёк, но документ ещё нужен (например, для разбирательства).**  
   Администратор может продлить срок хранения вручную (изменить `expires_at`). Открытый вопрос №73.

5. **Преподаватель хочет удалить загруженный документ до решения модератора.**  
   Разрешить отзыв документа: преподаватель может отменить заявку, документ удаляется, статус становится `cancelled`.

6. **Сбой при сохранении файлов или записи.**  
   Частичная загрузка не должна создавать запись; при ошибке файлы могут остаться в хранилище, необходима очистка.

### 17.6. Правила и ограничения

1. Верификация документов выполняется только модератором с правом `verify_tutor_documents`.
2. Типы документов: `passport`, `diploma`, `certificate`. Состав может быть расширен.
3. Для одного преподавателя может быть несколько документов одного типа (например, несколько сертификатов). Каждый документ проверяется отдельно.
4. Один документ может содержать несколько файлов.
5. После решения документ хранится в течение срока, по умолчанию 30 дней, затем файлы и запись удаляются.
6. Верификационные записи в `tutor_verifications` не удаляются и сохраняются, пока верификация действительна.
7. Уведомления преподавателю о результате проверки отправляются через личные сообщения на платформе (внутренняя переписка), дополнительно можно email/SMS (по настройкам).
8. При отклонении нового документа, если по этому типу уже была верификация, она по умолчанию сохраняется. Модератор может явно указать «отозвать верификацию» — тогда запись удаляется или деактивируется.
9. Документы доступны для просмотра только модератору с правом `verify_tutor_documents` и, возможно, администратору.
10. Персональные данные обрабатываются в соответствии с 152-ФЗ: согласие на обработку ПДн получается при регистрации, хранение файлов ограничено, серверы в РФ.

### 17.7. Изменения модели данных

**Таблица `verification_documents`:**

| Поле        | Тип                                            | Комментарий                                                                                             |
| ----------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| id          | BigInteger, PK                                 |                                                                                                         |
| tutor_id    | BigInteger, FK → `tutor_profiles.id`, NOT NULL | преподаватель                                                                                           |
| type        | String, NOT NULL                               | `passport`, `diploma`, `certificate`                                                                    |
| title       | String(200), NULL                              | для сертификата — название                                                                              |
| file_keys   | JSONB (или отдельная таблица)                  | ключи файлов в хранилище                                                                                |
| status      | String, NOT NULL, default 'pending'            | `pending`, `approved`, `rejected`, `cancelled`                                                          |
| reviewer_id | BigInteger, FK → `users.id`, NULL              | модератор                                                                                               |
| comment     | String(1000), NULL                             | причина отклонения                                                                                      |
| created_at  | datetime, NOT NULL                             | время загрузки                                                                                          |
| reviewed_at | datetime, NULL                                 | время решения                                                                                           |
| expires_at  | datetime, NULL                                 | когда удалить (устанавливается при решении: reviewed_at + 30 дней; может быть продлено администратором) |

**Таблица `tutor_verifications`** (единая таблица верификаций):

| Поле        | Тип                                                | Комментарий                             |
| ----------- | -------------------------------------------------- | --------------------------------------- |
| id          | BigInteger, PK                                     |                                         |
| tutor_id    | BigInteger, FK → `tutor_profiles.id`, NOT NULL     | преподаватель                           |
| type        | String, NOT NULL                                   | `passport`, `diploma`, `certificate`    |
| title       | String(200), NULL                                  | для сертификата — название              |
| verified_at | datetime, NOT NULL                                 | когда подтверждено                      |
| document_id | BigInteger, FK → `verification_documents.id`, NULL | связь с последним одобренным документом |
| is_active   | Boolean, NOT NULL, default true                    | активна ли верификация (можно отозвать) |

**Права:**

- `verify_tutor_documents` — новое право, назначается модераторам.

**Индексы и ограничения:**

- Индекс по `(tutor_id, type)` в `tutor_verifications`.
- Индекс по `(tutor_id, type, status)` в `verification_documents` для быстрого поиска активных документов.

**Правки согласованных правил:**

1. В разделе 7.6 п.2 (состав карточки репетитора) добавляются отметки верификации: «Личность подтверждена», «Образование подтверждено», «Сертификат подтверждён». Это повлияет на отображение в каталоге и профиле. Необходимо синхронизировать после завершения сценария.
2. Верификация документов — процесс, независимый от публичности профиля. Преподаватель может загружать документы до того, как его профиль станет публичным.
