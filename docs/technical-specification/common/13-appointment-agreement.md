## 13. Договорённость о занятии

### 13.1. Назначение

Процесс фиксирует факт, что ученик и репетитор в рамках переписки договорились о проведении занятия. Платформа опрашивает обе стороны, и только при взаимном подтверждении считает договорённость успешной, открывая возможность оставить отзыв (отзыв оставляет только ученик на репетитора — 14.8, №53).

Фактическое проведение занятия не отслеживается.

### 13.2. Участники, пред- и постусловия

**Участники:**

- авторизованный ученик (участник диалога);
- авторизованный репетитор (участник диалога);
- система (сервер) инициирует опрос, сохраняет ответы, определяет статус.

**Предусловия:**

- существует диалог между учеником и репетитором;
- обе стороны отправили хотя бы по одному сообщению в этом диалоге;
- в данном диалоге нет активного опроса (статус `pending`);
- опрос инициируется системой при выполнении условия (см. 13.4, шаг 1).

**Постусловия (успешное завершение при подтверждении обеими сторонами):**

- создана запись опроса со статусом «подтверждена»;
- ученик получает возможность оставить отзыв на репетитора (см. 13.6 п.6; правка к прежней формулировке — 14.8, №53);
- диалог остаётся доступным.

**Постусловия (если хотя бы одна сторона ответила отрицательно или не ответила в срок):**

- запись опроса получает статус «отклонена» или «не подтверждена»;
- возможность оставить отзыв не открывается;
- пользователи могут продолжать общение в этом диалоге или с другими пользователями.

### 13.3. Входные данные

Со стороны пользователей входными данными является только ответ на вопрос: «Удалось ли вам договориться о занятии?» (да/нет). Дополнительных полей нет.

### 13.4. Основной процесс

1. Система определяет, что для диалога выполнены условия инициации опроса: обе стороны отправили хотя бы одно сообщение и с момента последнего сообщения прошло не менее 24 часов.
2. Система создаёт запись опроса в таблице `agreement_surveys` со статусом `pending` и отправляет **обоим** участникам внутреннее уведомление с вопросом «Удалось ли вам договориться о занятии?». Внешние каналы (push, email) не используются.
3. Для каждого участника система создаёт отдельную запись в таблице `agreement_answers` с полями, отражающими состояние ответа. Для каждой стороны запускается собственный таймер ожидания: отсчёт начинается с момента, когда пользователь **прочитал** уведомление (поле `read_at` установлено). Если пользователь не открывает уведомление, таймер не стартует.
4. Ученик и репетитор независимо отвечают «Да» или «Нет».
5. Сервер сохраняет ответ каждой стороны в соответствующей записи `agreement_answers`, фиксируя время ответа.
6. Когда получены оба ответа или истекли оба таймера (для тех, кто не ответил), система определяет итоговый статус опроса:
   - **оба ответили «Да»** → `confirmed`;
   - **хотя бы один ответил «Нет»** → `rejected`;
   - **один или оба не ответили в срок** → `unconfirmed`.
7. Если статус `confirmed`:
   - система открывает ученику возможность оставить отзыв на репетитора;
   - в интерфейсе диалога может появиться индикатор «Вы договорились о занятии».
8. Если статус `rejected` или `unconfirmed`:
   - возможность отзыва не открывается;
   - пользователи могут продолжать общение. Если после отклонения в диалоге появились новые сообщения, система **может инициировать повторный опрос** через 24 часа после последнего сообщения (см. 13.6 п.3).
9. Диалог остаётся доступным в любом случае.

### 13.5. Ошибочные и альтернативные ветки

1. **Один из пользователей не отвечает в течение срока.**  
   Таймер для этого пользователя истекает, но если ответ поступит позже, он **сохраняется**, однако не меняет итоговый статус (который уже определён). Возможность отзыва не открывается.

2. **Оба пользователя ответили «Нет».**  
   Статус `rejected`. Пользователи могут продолжать общение в этом диалоге или с другими людьми.

3. **Пользователь уже ответил, но пытается ответить повторно.**  
   Сервер блокирует повторный ответ; пользователю показывается сообщение «Вы уже ответили на этот вопрос».

4. **Диалог был удалён до инициации опроса.**  
   Опрос не инициируется.

5. **Сбой при доставке внутреннего уведомления.**  
   Пользователь может увидеть вопрос в интерфейсе диалога или в разделе уведомлений при следующем входе.

6. **Оба пользователя не открыли уведомление.**  
   Таймеры не запускаются, опрос остаётся в статусе `pending` до тех пор, пока кто-то не прочитает. Ограничение по времени для такого случая не предусмотрено (можно добавить позже).

### 13.6. Правила и ограничения

1. **Условия инициации опроса.** Опрос инициируется, когда обе стороны отправили хотя бы одно сообщение и с момента последнего сообщения прошло не менее **24 часов**. Это значение конфигурируемое.

2. **Таймер ожидания ответа.** Для каждой стороны отдельный таймер длительностью **72 часа**, запускается с момента прочтения уведомления. Если пользователь не прочитал уведомление, таймер не идёт. Если пользователь не ответил до истечения таймера, его ответ в дальнейшем не влияет на статус, но сохраняется.

3. **Повторный опрос.** Если после отклонения (`rejected`) в диалоге появились новые сообщения, система может инициировать повторный опрос через 24 часа после последнего сообщения. Если новых сообщений не было, повторный опрос не проводится.

4. **Один активный опрос на диалог.** Повторный опрос не создаётся, пока текущий имеет статус `pending`.

5. **Симметричность.** Опрос получают оба участника. Ответы учитываются независимо.

6. **Отзыв после подтверждения.** При статусе `confirmed` ученик получает возможность оставить отзыв на репетитора. Репетитор отзыв на ученика не оставляет (правка к прежней формулировке — 14.8, №53). Детали — в сценарии отзывов (раздел 14).

7. **Приватность.** Ответы пользователей на вопрос о договорённости не показываются другой стороне до финализации статуса. После финализации можно показать итоговый статус, но не индивидуальные ответы.

8. **Влияние на другие функции.** Подтверждённая договорённость не приводит к автоматическому созданию покупки или финансовым действиям.

### 13.7. Изменения модели данных

Создать две связанные таблицы для опросов и ответов.

**Таблица `agreement_surveys`** — описывает сам факт опроса для диалога:

| Поле            | Тип                                                   | Комментарий                                       |
| --------------- | ----------------------------------------------------- | ------------------------------------------------- |
| id              | BigInteger, PK                                        |                                                   |
| conversation_id | BigInteger, FK → `conversations.id`, NOT NULL, UNIQUE | один активный опрос на диалог                     |
| status          | String (Enum), NOT NULL                               | `pending`, `confirmed`, `rejected`, `unconfirmed` |
| initiated_at    | datetime, NOT NULL                                    | когда создан опрос и отправлены уведомления       |
| resolved_at     | datetime, NULL                                        | когда определён итоговый статус                   |

Уникальный индекс на `conversation_id` гарантирует не более одного опроса на диалог (но после завершения можно создать новый, поэтому индекс может быть частичным `WHERE status = 'pending'`, либо просто уникальным по conversation_id, чтобы упростить; если нужно несколько опросов в истории, то нужно изменить ограничение на уникальность только для активных. Рекомендуется частичный уникальный индекс: `(conversation_id) WHERE status = 'pending'`).

**Таблица `agreement_answers`** — хранит индивидуальные ответы и таймеры:

| Поле         | Тип                                               | Комментарий                                              |
| ------------ | ------------------------------------------------- | -------------------------------------------------------- |
| id           | BigInteger, PK                                    |                                                          |
| survey_id    | BigInteger, FK → `agreement_surveys.id`, NOT NULL | к какому опросу относится                                |
| user_id      | BigInteger, FK → `users.id`, NOT NULL             | кто отвечает                                             |
| notified_at  | datetime, NULL                                    | когда отправлено внутреннее уведомление                  |
| read_at      | datetime, NULL                                    | когда пользователь прочитал уведомление (начало таймера) |
| response     | Boolean, NULL                                     | ответ: true = да, false = нет; null = ещё не ответил     |
| responded_at | datetime, NULL                                    | время ответа                                             |

Уникальный индекс `(survey_id, user_id)` — одна запись на каждого участника опроса.

Связь с отзывами: таблица `reviews` уже существует; при создании отзыва можно проверять наличие `confirmed` записи в `agreement_surveys` для соответствующего диалога.
