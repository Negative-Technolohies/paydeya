## 10. Ограничение сообщений

### 10.1. Назначение

Процесс ограничивает количество сообщений, которые инициатор диалога может отправить подряд, пока вторая сторона не ответила. Цель — снизить спам и защитить получателя от нежелательного потока сообщений.

Правило применяется симметрично: если диалог начал ученик — ограничение действует для ученика; если диалог начал репетитор — ограничение действует для репетитора.

После первого ответа второй стороны ограничение снимается полностью и в дальнейшем не применяется.

### 10.2. Участники, пред- и постусловия

**Участник:** авторизованный пользователь (ученик или репетитор), пытающийся отправить сообщение в существующий диалог, где он является инициатором.

**Предусловия:**

- существует диалог (`conversations`) между двумя участниками;
- пользователь авторизован и является одним из участников диалога;
- пользователь является инициатором диалога (отправил первое сообщение);
- вторая сторона ещё не ответила в этом диалоге (не отправила ни одного сообщения после создания диалога);
- пользователь уже отправил в этот диалог не менее 5 сообщений (включая удалённые).

**Постусловия (успешное завершение при допустимом действии):**

- сообщение сохранено в таблице `messages`;
- `conversations.last_message_at` обновлено;
- вторая сторона получила уведомление (если применимо);
- счётчик сообщений инициатора увеличился.

**Постусловия (при исчерпании лимита):**

- сообщение не сохраняется;
- пользователь видит сообщение об ошибке: «Вы достигли лимита сообщений. Дождитесь ответа собеседника»;
- диалог остаётся в прежнем состоянии.

### 10.3. Входные данные

| Поле              | Обязательность | Валидация                                                     |
| ----------------- | -------------- | ------------------------------------------------------------- |
| `conversation_id` | обязательно    | должен существовать, пользователь является участником         |
| `text`            | обязательно    | непустой, длина до `[уточнить, открытый вопрос №33]` символов |

### 10.4. Основной процесс

1. Пользователь (инициатор) пытается отправить сообщение в диалог.
2. Сервер находит диалог по `conversation_id`, проверяет, что пользователь является участником.
3. Сервер определяет, был ли уже ответ второй стороны:
   - ищет хотя бы одно сообщение в диалоге, где `sender_id` != `initiator_user_id` (вторая сторона);
   - если такое сообщение существует — лимит снят, переход к шагу 6.
4. Если ответа второй стороны ещё нет:
   - сервер подсчитывает количество сообщений от инициатора (`sender_id = initiator_user_id`) в этом диалоге, **включая удалённые** (записи с `deleted_at` не игнорируются);
   - если это количество >= 5, переход к шагу 5 (блокировка).
5. Если количество сообщений инициатора >= 5 и ответа нет:
   - сервер не создаёт сообщение;
   - возвращает ошибку с кодом/сообщением о достижении лимита;
   - пользователь видит: «Вы отправили максимальное количество сообщений. Дождитесь ответа собеседника».
6. Если лимит не исчерпан (сообщений меньше 5 или ответ уже был):
   - сервер создаёт новое сообщение;
   - сохраняет `created_at`;
   - обновляет `conversations.last_message_at`;
   - отправляет уведомление второй стороне (по правилам уведомлений).
7. Конец.

### 10.5. Ошибочные и альтернативные ветки

1. **Пользователь не является участником диалога.**  
   Попытка отправить сообщение в чужой диалог блокируется на уровне авторизации: сервер возвращает 403/404, сообщение не сохраняется.

2. **Пользователь является второй стороной (не инициатором).**  
   Лимит не применяется; сообщение отправляется свободно. (См. 10.6 п.1).

3. **Ответ второй стороны уже был, но инициатор снова пытается отправить много сообщений подряд.**  
   Лимит больше не действует; все сообщения отправляются свободно.

4. **Инициатор удалил одно или несколько своих сообщений.**  
   Удаление не влияет на подсчёт лимита: удалённые сообщения учитываются. При попытке отправить новое сообщение, если удалённое было пятым, лимит всё равно считается исчерпанным.

5. **Прошло длительное время, вторая сторона так и не ответила.**  
   Лимит не сбрасывается по времени (см. 10.6 п.3). Инициатор не может отправить больше сообщений, пока вторая сторона не ответит.

6. **Сбой при отправке уведомления.**  
   Сообщение сохраняется; уведомление может не дойти, но вторая сторона увидит новые сообщения при следующем заходе.

### 10.6. Правила и ограничения

1. Лимит применяется **только к инициатору диалога** и **только до первого ответа второй стороны**. После любого ответа второй стороны ограничение снимается полностью для обеих сторон навсегда.

2. Лимит составляет **5 сообщений** от инициатора подряд. Подсчитываются все сообщения инициатора, включая удалённые (`deleted_at` не влияет на подсчёт).

3. Сброс лимита по времени **не реализуется**. Если инициатор исчерпал лимит, он не сможет отправить новое сообщение, пока вторая сторона не ответит.

4. Пока лимит действует, при попытке отправить шестое сообщение сервер блокирует действие и возвращает пользователю сообщение о необходимости дождаться ответа.

5. Ограничение симметрично: если диалог начал репетитор, то для него действует тот же лимит до первого ответа ученика.

6. Проверка лимита выполняется сервером в момент отправки сообщения, а не на клиенте.

### 10.7. Изменения модели данных

Текущая модель данных не требует обязательных изменений для реализации лимита, так как все необходимые данные можно вычислить на лету:

- определение инициатора: отправитель самого раннего сообщения в диалоге (`MIN(created_at)` среди сообщений);
- наличие ответа второй стороны: существование хотя бы одного сообщения, где `sender_id` != инициатор;
- подсчёт сообщений инициатора: `COUNT(*)` по `messages` с `conversation_id` и `sender_id = инициатор`, **без фильтра по `deleted_at`**.

Для реализации лимита и явной фиксации инициатора диалога **обязательно** добавить в таблицу `conversations`:

| Поле           | Тип                                   | Комментарий                                                                                                                    |
| -------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `initiator_id` | BigInteger, FK → `users.id`, NOT NULL | Определяет, кто начал диалог (отправил первое сообщение). Используется для применения лимита до первого ответа второй стороны. |

Подсчёт сообщений инициатора выполняется по `messages.sender_id` = `initiator_id`, включая удалённые (`deleted_at` не фильтруется). Поле `initiator_id` заполняется при создании диалога (в разделах 8 и 9) и не меняется в дальнейшем.

Остальная модель данных без изменений.
