## 11. Удаление сообщения

### 11.1. Назначение

Процесс позволяет пользователю удалить собственное отправленное сообщение в диалоге. Удаление скрывает содержимое сообщения и заменяет его на отметку «Сообщение удалено». Редактирование сообщений не предусмотрено.

Правило применяется симметрично: и ученик, и репетитор могут удалять только свои собственные сообщения.

### 11.2. Участники, пред- и постусловия

**Участник:** авторизованный пользователь (ученик или репетитор), являющийся отправителем сообщения.

**Предусловия:**

- пользователь авторизован и активен;
- существует сообщение с указанным идентификатором;
- пользователь является отправителем этого сообщения (`messages.sender_id = текущий пользователь`);
- сообщение ещё не удалено (`messages.deleted_at IS NULL`).

**Постусловия (успешное завершение):**

- сообщение помечено удалённым: `deleted_at` установлено в текущее время;
- содержимое сообщения недоступно для отображения другим участникам диалога;
- в интерфейсе на месте сообщения отображается отметка «Сообщение удалено»;
- другие свойства диалога (`last_message_at`, состав участников) не изменяются;
- удаление не влияет на подсчёт лимита сообщений (удалённые сообщения учитываются — см. 10.6 п.2).

### 11.3. Входные данные

| Поле               | Обязательность | Валидация                             |
| ------------------ | -------------- | ------------------------------------- |
| `message_id`       | обязательно    | идентификатор существующего сообщения |
| Действие «удалить» | —              | только для своего сообщения           |

Дополнительных текстовых полей нет.

### 11.4. Основной процесс

1. Пользователь открывает диалог и выбирает собственное сообщение.
2. Пользователь нажимает «Удалить».
3. Клиент отправляет на сервер запрос с идентификатором сообщения.
4. Сервер проверяет:
   - пользователь авторизован;
   - сообщение существует;
   - `sender_id` сообщения совпадает с идентификатором текущего пользователя;
   - `deleted_at` сообщения ещё не установлено.
5. Если хотя бы одна проверка не пройдена — ветка 11.5.1 или 11.5.2.
6. При успехе сервер устанавливает `messages.deleted_at = текущее время` (UTC).
7. Сервер сохраняет изменения.
8. Сервер возвращает подтверждение.
9. В интерфейсе у всех участников диалога данное сообщение заменяется на отметку «Сообщение удалено». Оригинальный текст больше не отображается.

### 11.5. Ошибочные и альтернативные ветки

1. **Попытка удалить чужое сообщение.**  
   Сервер возвращает ошибку доступа (403). Сообщение остаётся неизменным.

2. **Сообщение уже удалено.**  
   Повторное удаление невозможно; сервер может вернуть 404 или сообщение «Сообщение уже удалено».

3. **Сообщение не найдено.**  
   Сервер возвращает 404. Никаких изменений.

4. **Истекла сессия.**  
   Пользователь перенаправляется на повторный вход; после входа может повторить действие.

5. **Попытка редактирования сообщения.**  
   Редактирование не предусмотрено. В интерфейсе отсутствует соответствующая кнопка; сервер не поддерживает операцию. Попытка отправить запрос редактирования приведёт к ошибке метода.

### 11.6. Правила и ограничения

1. Удалять можно только собственные сообщения (отправитель = текущий пользователь).
2. Удаление необратимо: восстановить сообщение невозможно.
3. Удаление не изменяет факт существования сообщения — запись остаётся в базе данных с установленным `deleted_at`.
4. Удаление не влияет на лимит сообщений: удалённые сообщения учитываются при подсчёте количества сообщений инициатора (см. 10.6 п.2).
5. Редактирование сообщений отсутствует; можно только удалить.
6. Удаление сообщения не приводит к удалению диалога или других сообщений.
7. Содержимое удалённого сообщения не должно отображаться никому, включая отправителя. В интерфейсе показывается только заглушка.
8. Удалённое сообщение продолжает влиять на сортировку диалога по времени последнего сообщения (`last_message_at`), если оно было последним на момент удаления? Уточнение: удаление не меняет `last_message_at`, так как в диалоге могло остаться более позднее сообщение, но если удалено последнее, `last_message_at` остаётся прежним (время удалённого сообщения). Это допустимо, т.к. диалог всё ещё содержит сообщения.

### 11.7. Изменения модели данных

Текущая таблица `messages` уже содержит поле `deleted_at` (datetime, NULL). Для реализации сценария достаточно использовать это поле.

Дополнительных изменений не требуется. Поле `content` при удалении **не обнуляется** — текст остаётся в базе для аудита, но скрывается через `deleted_at` и не отображается никому.
