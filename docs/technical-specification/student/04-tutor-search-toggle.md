## 6. Включение и отключение поиска репетитора

### 6.1. Назначение

Процесс управляет режимом поиска: ученик явно заявляет платформе, ищет ли он репетитора прямо сейчас. Статус определяет:

- видимость активных анкет репетиторам (совместно с правилом 5.6 п. 5);
- возможность начинать **новые** диалоги (в обе стороны);
- не влияет на существующие диалоги и остальной функционал.

Граница разделов: здесь — управление статусом и его последствия. Механика отклика репетитора на анкету описывается в сценариях репетитора; механика создания диалога — в разделе переписки.

### 6.2. Участники, пред- и постусловия

**Участник:** авторизованный ученик с активной учётной записью.

**Постусловия (после включения):**

- статус «Ищу репетитора» установлен;
- активные анкеты видимы репетиторам (при наличии таковых);
- ученик может инициировать новые диалоги с репетиторами; репетиторы могут откликаться на его анкеты.

**Постусловия (после отключения):**

- статус снят; анкеты скрыты из выдач для репетиторов;
- новые отклики репетиторов невозможны;
- ученик не может инициировать новые диалоги с репетиторами;
- существующие диалоги продолжают работать в обе стороны без ограничений;
- доступ к платформе сохранён полностью (просмотр каталога, профилей, отзывов, контента, своих анкет и переписки).

### 6.3. Входные данные

Отсутствуют. Действие — переключатель «Ищу репетитора» в личном кабинете. Состояние хранится в профиле ученика (`is_searching`, 4.7).

### 6.4. Основной процесс

**Включение:**

1. Ученик в личном кабинете включает переключатель «Ищу репетитора».
2. Сервер проверяет состояние учётной записи (активна).
3. Сервер устанавливает статус. Если активных анкет нет — показывается предупреждение (ветка 6.5.1), статус при этом включается.
4. Активные анкеты ученика становятся видимыми подходящим репетиторам — тем, чьи фильтры (предмет, уровень, бюджет, формат, город) пересекаются с параметрами анкеты (5.4, шаг 9).
5. Репетиторы могут откликаться на анкеты; отклик создаёт диалог и уведомляет ученика (детали — сценарии репетитора).

**Отключение:**

1. Ученик выключает переключатель.
2. Сервер снимает статус.
3. Анкеты исключаются из выдач для репетиторов (см. 6.6, п. 6 — про «уже открытые» карточки).
4. Новые отклики репетиторов блокируются; проверка выполняется сервером в момент отклика, а не в момент показа анкеты (ветка 6.5.2).
5. Существующие диалоги продолжают работать в обе стороны: обе стороны могут писать, лимит 5 сообщений действует как обычно, уведомления доставляются.
6. Отключение никак не анонсируется репетиторам — действие приватно.
7. Ученик сохраняет доступ к просмотру контента, каталога репетиторов, профилей, отзывов, а также к своим анкетам и переписке.

**Попытка написать новому репетитору при выключенном поиске:**

1. Ученик открывает профиль репетитора, с которым диалога ещё нет, и нажимает «Написать» (кнопка не блокируется заранее — статус мог измениться).
2. Сервер отклоняет создание диалога.
3. Ученику показывается сообщение: «Чтобы начать общение с новым преподавателем, включите поиск репетитора» с кнопкой «Включить поиск» прямо в сообщении `[Открытый вопрос №20]`.
4. Если ученик включает поиск через эту кнопку — создание диалога продолжается автоматически, без повторного поиска репетитора `[Открытый вопрос №20]`.

### 6.5. Ошибочные и альтернативные ветки

1. **Включение при отсутствии активных анкет.** Предупреждение «Без активной анкеты репетиторы вас не увидят» со ссылкой на «Мои анкеты». Статус включается `[Открытый вопрос №18]`. Следствие (зафиксировано как правило): ученик с включённым поиском, но без анкет может писать новым репетиторам — гейт один, и это статус поиска, а не наличие анкеты (см. 6.6, п. 3).
2. **Гонка: репетитор открывает анкету, ученик в этот момент отключает поиск, репетитор нажимает «Откликнуться».** Отклик отклоняется сервером; репетитор видит сообщение «Ученик приостановил поиск» `[Открытый вопрос №19]`. Никаких диалогов и уведомлений ученику при этом не создаётся.
3. **Активация анкеты при выключенном поиске.** Разрешена; анкета получит статус «активная», но останется невидимой. Система предлагает включить поиск (5.4, шаг 8 — поведение уже согласовано там).
4. **Отправка сообщения в существующий диалог при выключенном поиске.** Не является ошибкой — разрешена обеим сторонам.

### 6.6. Правила и ограничения

1. Переключатель доступен только владельцу профиля.
2. Видимость анкеты репетитору = анкета активна **И** статус «Ищу репетитора» включён (5.6, п. 5).
3. Гейт новых диалогов — один: статус поиска. Инициировать новый диалог (в любую сторону) можно только при включённом статусе. Наличие анкеты для этого не требуется. Существующие диалоги гейтом не затрагиваются.
4. Репетитор в v1 может начать диалог с учеником только через отклик на анкету — других путей нет, профили учеников не публикуются (решение №7).
5. Все проверки статуса выполняются сервером в момент действия (создание диалога, отклик), а не в момент отображения интерфейса.
6. Скрытие анкеты: исключается из выдач при следующем формировании списка; уже открытая у репетитора карточка анкеты не «отзывается» принудительно, но отклик по ней пройдёт проверку (ветка 6.5.2).
7. Переключение статуса не анонсируется другим пользователям.
8. Лимитов на частоту переключения нет (действие дешёвое и не создаёт нагрузки на других пользователей).
9. Статус не влияет на: редактирование и активацию анкет, просмотр контента, существующие диалоги и их лимиты, уведомления в существующих диалогах.

### 6.7. Изменения модели данных

Отсутствуют. Поле `is_searching` введено в 4.7/5.7. Правила гейта реализуются серверными проверками в процессах создания диалога и отклика (разделы переписки и сценариев репетитора — при их написании сослаться на 6.6, п. 3–5).

История переключений статуса (когда включал/выключал) в v1 не хранится; если позже понадобится для аналитики воронки — отдельной задачей, не миграцией сейчас.
