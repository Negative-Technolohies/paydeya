## 5. Создание анкеты для поиска репетитора

### 5.1. Назначение

Процесс создаёт анкету — описание задачи ученика («ищу репетитора по математике для подготовки к ЕГЭ, онлайн, бюджет 1500–2500 ₽»), по которой репетиторы находят ученика, а платформа подбирает кандидатов.

Граница разделов: здесь описаны действия ученика над анкетой. Просмотр анкет и отклики репетиторов, а также подборка репетиторов для ученика — отдельные сценарии.

### 5.2. Участники, пред- и постусловия

**Участник:** авторизованный ученик с заполненным профилем.

**Предусловия:**

- регистрация завершена;
- в профиле указан уровень образования (обязательное поле профиля).

**Постусловия (успех):**

- анкета создана в статусе «черновик» либо «активная»;
- если активирована — она единственная активная по этому предмету; активные анкеты по другим предметам не затронуты;
- при включённом статусе «Ищу репетитора» анкета видна репетиторам в составе данных из 5.6, п. 4.

### 5.3. Входные данные

| Поле                | Обязательность           | Валидация                                                                                                                     |
| ------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| Предмет             | да                       | выбор из справочника `subjects`; справочник единый для анкет и репетиторов                                                    |
| Заголовок           | нет                      | до 100 символов; если не заполнен — формируется автоматически из предмета и уровня/цели `[Предложение — Открытый вопрос №17]` |
| Цель обучения       | нет                      | свободный текст, до 300 символов, без разметки                                                                                |
| Уровень образования | —                        | не вводится в анкете, берётся из профиля `[Правка №1 — см. конец раздела]`                                                    |
| Бюджет              | да                       | диапазон «от–до» в ₽ за занятие (60 мин) либо признак «договорная»; «от» ≤ «до»; при «договорной» границы не указываются      |
| Формат занятий      | да                       | онлайн / офлайн / любой                                                                                                       |
| Город               | да, если формат «офлайн» | выбор из справочника `cities`; предзаполняется из профиля                                                                     |
| Удобное время       | нет                      | до 300 символов                                                                                                               |
| Комментарий         | нет                      | до 1000 символов                                                                                                              |

Для сохранения **черновика** достаточно предмета. Полная обязательность полей проверяется при **активации**.

### 5.4. Основной процесс

1. Ученик из кабинета открывает «Мои анкеты» → «Создать анкету».
2. Система показывает форму; город предзаполнен из профиля (если указан).
3. Ученик заполняет поля.
4. Перед сохранением отображается предпросмотр анкеты **в том виде, в котором её увидят репетиторы** — состав данных согласно 5.6, п. 4.
5. Ученик сохраняет анкету. Сервер валидирует (для черновика — предмет), создаёт анкету в статусе «черновик».
6. Ученик нажимает «Сделать активной». Сервер проверяет:
   - заполненность всех обязательных полей (5.3);
   - отсутствие другой активной анкеты этого ученика по этому же предмету;
   - непревышение лимитов (5.6, п. 3).
7. При успехе анкета переводится в статус «активная», фиксируется время активации. Активные анкеты по другим предметам не затрагиваются.
8. Если статус «Ищу репетитора» выключен — система предлагает его включить; до включения анкета репетиторам не видна.
9. При включённом статусе анкета появляется в списке анкет для репетиторов. Доступные репетиторам фильтры: предмет, уровень образования, бюджет, формат, город, свежесть. Фильтра по цели нет — цель видна в карточке, оценивается глазами.
10. Система показывает ученику первичную подборку репетиторов по параметрам анкеты `[Открытый вопрос №15]`.

### 5.5. Ошибочные и альтернативные ветки

1. **Ошибки валидации.** Ошибки по полям в форме, введённые данные не теряются, анкета не сохраняется.
2. **Формат «офлайн» без города.** Блокирующая ошибка при сохранении и активации: офлайн-анкета без города не имеет смысла для поиска.
3. **Активация с незаполненными обязательными полями.** Список незаполненных полей, анкета остаётся черновиком.
4. **Активная анкета по этому предмету уже существует.** Активация блокируется с сообщением «По этому предмету уже есть активная анкета» и ссылкой на неё: отредактировать существующую либо заархивировать её и активировать новую. Автозамены не делаем — молчаливая перезапись уничтожит данные существующей анкеты.
5. **Достигнут лимит анкет** (10). Сообщение с предложением удалить ненужную.
6. **Редактирование активной анкеты с ошибкой.** Сохранение отклоняется, репетиторам продолжает показываться прежняя версия.
7. **Истекла сессия.** Аналогично 4.5.3.

### 5.6. Правила и ограничения

1. Создание, редактирование, активация, архивация, удаление — только владельцем.
2. Активных анкет может быть несколько, но **не более одной по каждому предмету**. Анкеты по разным предметам активны одновременно. Правило защищается на уровне БД (5.7).
3. Лимиты — конфигурируемые параметры системы, не зашитые константы: сейчас максимум 10 анкет на ученика (любых статусов), отдельного лимита активных нет. Будущие лимиты (например, 3 активных, расширение по подписке) вводятся изменением параметров, без миграций.
4. **Состав карточки анкеты, видимой репетитору** (до переписки): ФИО (ФИО в карточке анкеты читается из учётной записи), уровень образования, город, предмет, заголовок, цель, бюджет, формат, расписание, комментарий, время активации. **Не показываются:** аватар, email, телефон и любые контактные данные. Аватар становится виден в переписке; контактные данные не видны нигде на платформе.
5. Видимость анкеты репетиторам = анкета активна **И** статус «Ищу репетитора» включён.
6. Статус «Ищу репетитора» включается автоматически при первой активации анкеты, дальше управляется вручную переключателем в кабинете. Автоматического выключения нет `[Открытый вопрос №16]`.
7. Редактирование активной анкеты разрешено; изменения применяются к показу репетиторам немедленно.
8. Премодерации анкет нет, контроль — постмодерация по жалобам (единообразно с профилем).
9. TTL активной анкеты в v1 нет `[Открытый вопрос №16]`.
10. Удаление анкеты безвозвратно, включая активную — при этом ученик перестаёт быть виден репетиторам по этому предмету, пока не активирует другую.

### 5.7. Изменения модели данных

Целевая структура `questionnaires` (правки к текущей схеме):

| Поле                     | Тип                                                   | Комментарий                                                     |
| ------------------------ | ----------------------------------------------------- | --------------------------------------------------------------- |
| id                       | BigInteger, PK                                        |                                                                 |
| student_id               | BigInteger, FK → `student_profiles.id`, NOT NULL      |                                                                 |
| subject_id               | BigInteger, FK → `subjects.id`, NOT NULL              | добавить                                                        |
| title                    | String(100), NULL                                     | сейчас NOT NULL — сделать необязательным (№17)                  |
| goal                     | String(300), NULL                                     | замена `goals Text`: необязательное поле + лимит длины          |
| budget_min / budget_max  | Numeric, NULL                                         | замена одиночного `budget` на диапазон                          |
| budget_negotiable        | Boolean, NOT NULL, default false                      | признак «договорная»                                            |
| format                   | enum (online/offline/any), NOT NULL                   | добавить                                                        |
| city_id                  | BigInteger, FK → `cities.id`, NULL                    | добавить; обязателен при format = offline (контроль приложения) |
| schedule                 | String(300), NULL                                     | добавить                                                        |
| description              | String(1000), NULL                                    | добавить                                                        |
| status                   | enum (draft/active/archived), NOT NULL, default draft | замена `search_status Boolean`: трёхстатусная модель            |
| created_at               | datetime, NOT NULL                                    |                                                                 |
| updated_at, activated_at | datetime, NULL                                        | добавить                                                        |

Сопутствующие изменения:

- `student_profiles`: удалить `verified` (состояние подтверждения живёт на `users` — решение раздела 3); удалить `active_questionnaire_id` (несовместим с несколькими активными анкетами; источник правды — только `status` анкеты); `city` → `city_id` FK → `cities`; добавить `is_searching` (Boolean, NOT NULL, default false) — глобальный переключатель «Ищу репетитора»; `grade` → `education_level_id` FK → `education_levels`.
- Новые справочники: `cities` (id, name, timezone), `subjects` (id, name — уникально), `education_levels` (id, name) — состав уровней: начальная школа, средняя школа, старшая школа, студент/высшее `[Предложение — финальные названия уточнить]`.
- **Частичный уникальный индекс** `(student_id, subject_id) WHERE status = 'active'` — обязательное требование: правило «одна активная анкета на предмет» должно защищаться на уровне БД, а не только кодом.
- Старый `search_status` не переиспользуется: он смешивал два понятия — состояние анкеты и глобальный статус поиска. В новой модели они разделены (`status` анкеты + `is_searching` профиля).

**Правки согласованных правил (отклонения от исходного сценария):**

1. **Класс убран из анкеты, берётся из профиля динамически** (шаг 4 сценария) — единственный источник правды; анкета не должна «замораживать» уровень на момент создания.
