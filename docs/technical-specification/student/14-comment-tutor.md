## 14. Отзыв о преподавателе

### 14.1. Назначение

Процесс позволяет ученику оставить отзыв о преподавателе после успешно подтверждённой договорённости. Отзыв содержит оценку от 1 до 5 и текст. После публикации отзыв отображается в профиле преподавателя, учитывается в его среднем рейтинге и увеличивает количество отзывов.

Ученик может изменить или удалить свой отзыв. При удалении отзыв перестаёт учитываться в рейтинге и количестве, но запись сохраняется в базе (мягкое удаление) для возможности аудита. После удаления ученик может оставить новый отзыв.

Репетитор может ответить на отзыв (ответ отображается под отзывом).

### 14.2. Участники, пред- и постусловия

**Участники:**

- авторизованный ученик (автор отзыва);
- авторизованный репетитор (получатель отзыва);
- система (сервер) создаёт, изменяет, удаляет отзыв, пересчитывает агрегаты.

**Предусловия:**

- ученик и репетитор имеют активные учётные записи;
- между ними существует диалог (`conversations`);
- в этом диалоге есть подтверждённая договорённость (`agreement_surveys.status = 'confirmed'`);
- для данной пары ученик-репетитор нет активного (не удалённого) отзыва.

**Постусловия (успешное создание отзыва):**

- создана запись отзыва со статусом «опубликован»;
- отзыв отображается в профиле репетитора;
- рейтинг репетитора пересчитан (среднее арифметическое всех опубликованных отзывов);
- количество отзывов репетитора увеличено;
- ученик видит свой отзыв и может его редактировать или удалить.

**Постусловия (успешное редактирование):**

- текст и/или оценка отзыва обновлены;
- рейтинг репетитора пересчитан.

**Постусловия (успешное удаление):**

- отзыв помечен удалённым (`deleted_at` установлено);
- отзыв скрыт из профиля репетитора;
- рейтинг и количество отзывов пересчитаны (отзыв больше не учитывается);
- ученик может создать новый отзыв (активного отзыва больше нет).

### 14.3. Входные данные

При создании отзыва:

| Поле       | Обязательность | Валидация                                            |
| ---------- | -------------- | ---------------------------------------------------- |
| `tutor_id` | обязательно    | идентификатор репетитора, которому оставляется отзыв |
| `rating`   | обязательно    | целое число от 1 до 5                                |
| `text`     | обязательно    | непустой, длина до 2000 символов, без разметки       |

При редактировании — те же поля, что и при создании, но идентификатор отзыва уже известен.

При удалении — только идентификатор отзыва.

### 14.4. Основной процесс

**Создание отзыва:**

1. Ученик находится в диалоге с репетитором (или в профиле репетитора), где доступна кнопка «Оставить отзыв» (она появляется только при выполнении условий: подтверждённая договорённость и отсутствие активного отзыва).
2. Ученик открывает форму отзыва.
3. Ученик выбирает оценку (1–5) и пишет текст.
4. Ученик нажимает «Отправить».
5. Сервер проверяет:
   - ученик авторизован;
   - между учеником и репетитором существует диалог;
   - в этом диалоге есть подтверждённая договорённость (`agreement_surveys.status = 'confirmed'`);
   - для пары ученик-репетитор нет активного отзыва (с `deleted_at IS NULL`);
   - рейтинг в диапазоне 1–5, текст непустой и не превышает 2000 символов.
6. Если проверки не пройдены — соответствующая ветка из 14.5.
7. При успехе сервер создаёт запись в таблице `reviews` с полями: author_id = ученик, target_id = репетитор, rating, text, agreement_id = идентификатор подтверждённой договорённости, created_at = сейчас.
8. Сервер обновляет агрегаты репетитора:
   - пересчитывает средний рейтинг (`avg_rating`) как среднее арифметическое оценок всех опубликованных отзывов этого репетитора;
   - увеличивает счётчик отзывов (`reviews_count`) на 1.
9. Отзыв сразу становится видимым в профиле репетитора.
10. Ученик видит подтверждение.

**Редактирование отзыва:**

1. Ученик открывает свой существующий отзыв (например, в профиле репетитора или в списке своих отзывов).
2. Нажимает «Редактировать».
3. Изменяет оценку или текст.
4. Сохраняет.
5. Сервер проверяет, что отзыв принадлежит ученику и не удалён.
6. Обновляет поля `rating`, `text`, `updated_at`.
7. Пересчитывает средний рейтинг репетитора (если изменилась оценка).

**Удаление отзыва:**

1. Ученик открывает свой отзыв.
2. Нажимает «Удалить».
3. Подтверждает действие.
4. Сервер проверяет, что отзыв принадлежит ученику и не удалён.
5. Устанавливает `deleted_at` = текущее время.
6. Пересчитывает агрегаты репетитора: исключает этот отзыв из среднего рейтинга и уменьшает счётчик отзывов.
7. Отзыв скрывается из профиля репетитора.

**Ответ репетитора:**

1. Репетитор видит опубликованный отзыв в своём профиле.
2. Нажимает «Ответить».
3. Вводит текст ответа.
4. Сохраняет.
5. Сервер создаёт запись в таблице `review_replies`, привязанную к отзыву.
6. Ответ отображается под отзывом.
7. Репетитор может редактировать или удалить свой ответ (детали не раскрыты в сценарии — открытый вопрос №55).

### 14.5. Ошибочные и альтернативные ветки

1. **Нет подтверждённой договорённости.**  
   Кнопка «Оставить отзыв» не показывается или при попытке отправить сервер возвращает ошибку «Чтобы оставить отзыв, необходимо подтвердить договорённость о занятии».

2. **Активный отзыв уже существует.**  
   Ученик не может создать второй; если он пытается отправить форму, сервер блокирует и предлагает редактировать существующий отзыв.

3. **Неверная оценка (меньше 1 или больше 5, или не целое).**  
   Форма не отправляется (клиентская валидация) или сервер возвращает ошибку.

4. **Пустой текст отзыва.**  
   Ошибка валидации, отзыв не сохраняется.

5. **Слишком длинный текст (>2000 символов).**  
   Ошибка валидации.

6. **Попытка отредактировать чужой отзыв.**  
   Сервер возвращает 403, отзыв не изменяется.

7. **Попытка удалить уже удалённый отзыв.**  
   Сервер возвращает сообщение «Отзыв уже удалён».

8. **Удаление отзыва, если рейтинг репетитора был основан только на нём.**  
   После удаления `avg_rating` становится NULL или 0 (в зависимости от политики отображения), `reviews_count` = 0.

9. **Сбой при пересчёте рейтинга.**  
   Отзыв сохраняется, но агрегаты не обновляются. Необходимо предусмотреть механизм фоновой пересчёта или транзакционность. Открытый вопрос №54.

### 14.6. Правила и ограничения

1. Один ученик может иметь **только один активный (не удалённый) отзыв** на одного репетитора.
2. Отзыв можно создать только при наличии подтверждённой договорённости (`agreement_surveys.status = 'confirmed'`) в диалоге между этими пользователями.
3. Отзыв содержит обязательную оценку от 1 до 5 и обязательный текст длиной до 2000 символов.
4. Оценка — целое число, без дробной части.
5. Средний рейтинг репетитора рассчитывается как среднее арифметическое всех **опубликованных** (не удалённых) отзывов. Количество отзывов — число таких отзывов.
6. При удалении отзыв не удаляется физически, а помечается `deleted_at`; он исключается из расчёта рейтинга и количества.
7. После удаления отзыва ученик может оставить новый отзыв (при сохранении условий договорённости).
8. Редактирование отзыва разрешено только автору. Изменение оценки или текста сразу влияет на рейтинг.
9. Ответ репетитора привязан к конкретному отзыву; репетитор может иметь только один ответ на один отзыв (или несколько? — уточнить, открытый вопрос №55).
10. Отзывы не проходят премодерацию, публикуются сразу. Жалобы на отзывы обрабатываются по общему сценарию жалоб (раздел 12).
11. Все операции с отзывами (создание, редактирование, удаление) должны выполняться транзакционно вместе с пересчётом агрегатов, чтобы избежать рассинхронизации.

### 14.7. Изменения модели данных

Текущая таблица `reviews` требует изменений и дополнений:

**Таблица `reviews` (обновлённая):**

| Поле         | Тип                                               | Комментарий                                                   |
| ------------ | ------------------------------------------------- | ------------------------------------------------------------- |
| id           | BigInteger, PK                                    |                                                               |
| author_id    | BigInteger, FK → `users.id`, NOT NULL             | ученик, оставивший отзыв                                      |
| target_id    | BigInteger, FK → `users.id`, NOT NULL             | репетитор, которому оставлен отзыв                            |
| agreement_id | BigInteger, FK → `agreement_surveys.id`, NOT NULL | на основании какой подтверждённой договорённости создан отзыв |
| rating       | Integer, NOT NULL                                 | оценка 1–5                                                    |
| text         | String(2000), NOT NULL                            | текст отзыва                                                  |
| created_at   | datetime, NOT NULL                                | время создания                                                |
| updated_at   | datetime, NULL                                    | время последнего редактирования                               |
| deleted_at   | datetime, NULL                                    | время удаления (мягкое удаление)                              |

**Индексы:**

- Уникальный частичный индекс на `(author_id, target_id) WHERE deleted_at IS NULL` — гарантирует один активный отзыв на пару.
- Индекс по `target_id` и `deleted_at` для быстрого пересчёта рейтинга.

**Обновление агрегатов в `tutor_profiles`:**

- `avg_rating` (Numeric(2,1), NULL) — средний рейтинг по опубликованным отзывам.
- `reviews_count` (Integer, NOT NULL, default 0) — количество опубликованных отзывов.

Эти поля уже обсуждались в 7.7; теперь они становятся обязательными.

**Новая таблица `review_replies`** (если ответ репетитора будет реализован):

| Поле       | Тип                                     | Комментарий                 |
| ---------- | --------------------------------------- | --------------------------- |
| id         | BigInteger, PK                          |                             |
| review_id  | BigInteger, FK → `reviews.id`, NOT NULL | к какому отзыву ответ       |
| tutor_id   | BigInteger, FK → `users.id`, NOT NULL   | репетитор, написавший ответ |
| text       | String(1000), NOT NULL                  | текст ответа                |
| created_at | datetime, NOT NULL                      |                             |
| updated_at | datetime, NULL                          |                             |
| deleted_at | datetime, NULL                          | мягкое удаление             |

Пока эта таблица вводится как предложение, так как сценарий не детализирует ответ.
