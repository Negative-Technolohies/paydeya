## 7. Поиск репетитора через каталог

### 7.1. Назначение

Процесс позволяет ученику самостоятельно подобрать репетитора в каталоге по параметрам и перейти к его профилю.

Граница разделов: здесь — фильтры, список карточек и их состав. Просмотр полного профиля репетитора — отдельный сценарий (состав профиля определяется там). Начало переписки — сценарий переписки; гейт новых диалогов описан в 6.6, п. 3. Состав первичной подборки при активации анкеты — №15, здесь только упоминается.

### 7.2. Участники, пред- и постусловия

**Участник:** авторизованный ученик с активной учётной записью. Статус «Ищу репетитора» может быть любым — каталог доступен и при выключенном поиске (6.2, 6.6 п. 9), пресеты анкет при этом также доступны (поиск самим учеником не гейтится статусом).

**Предусловия:** аккаунт активен. Доступ неавторизованных пользователей к каталогу — `[№25, на согласовании]`.

**Постусловия:** отсутствуют — раздел read-only, состояние системы не меняется. Аналитика просмотров/кликов — вне рамок v1 `[Предложение]`.

### 7.3. Входные данные

Фильтры поиска:

| Фильтр                      | Предустановка                           | Значения                                                                                                                |
| --------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Предмет                     | из активной анкеты `[№21]`              | выбор из `subjects`                                                                                                     |
| Цена                        | из бюджета активной анкеты `[№21]`      | диапазон «от–до», ₽ за занятие (60 мин); учитываются **обе границы** — цена репетитора должна попадать в диапазон (№22) |
| Рейтинг                     | нет                                     | минимальный порог из фиксированного набора: 4,0 / 4,5 / 4,8 `[Предложение]`                                             |
| Подтверждённая квалификация | нет (выкл.)                             | вкл. — только репетиторы с подтверждённой квалификацией                                                                 |
| Формат                      | из анкеты                               | онлайн / офлайн / любой                                                                                                 |
| Город                       | из анкеты (для офлайн)                  | выбор из `cities`                                                                                                       |
| Уровень образования         | из профиля ученика                      | выбор из `education_levels`                                                                                             |
| Сортировка                  | по умолчанию — `[№24, на согласовании]` | рейтинг / цена ↑ / цена ↓ / количество отзывов / новые `[Предложение]`                                                  |

Предустановки из анкеты применяются **только как стартовые значения формы** — ученик видит их и может изменить любое.

### 7.4. Основной процесс

1. Ученик открывает каталог преподавателей.
2. Сервер определяет активные анкеты ученика:
   - **активных анкет нет** — каталог открывается без предустановок (все репетиторы, сортировка по умолчанию); показывается ненавязчивая подсказка «Создайте анкету — подберём репетиторов автоматически» `[Предложение]`; просмотр не блокируется;
   - **одна активная анкета** — фильтры предзаполняются её параметрами: предмет, бюджет, формат, город (для офлайн); уровень — из профиля;
   - **несколько активных анкет** — `[Не определено, №21 в обсуждении]`. Рабочее поведение до решения: предустановка от последней активированной анкеты, над фильтрами — чипы быстрого переключения между активными анкетами (анкета = пресет фильтров). Изменение решения по №21 затрагивает только этот шаг.
3. Сервер формирует список: репетиторы в активном статусе с опубликованным профилем, прошедшие фильтры; выбранная сортировка; первая страница (20 карточек, подгрузка при прокрутке `[Предложение]`).
4. Ученик просматривает карточки. Состав карточки — 7.6, п. 2 `[черновик, №23]`.
5. Ученик изменяет фильтры и применяет их (предложение: применение без кнопки, с задержкой на окончание ввода `[Предложение]`). Сервер перестраивает список; отображается количество найденных репетиторов.
6. Предустановленные фильтры сбрасываются кнопкой «Сбросить» — возвращается полный список `[Предложение]`.
7. Ученик выбирает репетитора и открывает его профиль — дальнейшее описано в сценарии профиля репетитора. Из профиля «Написать» — сценарий переписки с проверкой 6.6, п. 3.

### 7.5. Ошибочные и альтернативные ветки

1. **Ничего не найдено.** Пустое состояние: «По вашим фильтрам ничего не найдено» + предложения ослабить бюджет, снять ограничение по городу/формату. Фильтры сохраняются, доступны к правке.
2. **Некорректные значения фильтра** (цена «от» > «до»). Ошибка по полю, список не перестраивается — остаётся прежний.
3. **Несколько активных анкет.** Ветка 7.4, шаг 2 — поведение не утверждено, №21.
4. **Каталог пуст** (платформа на старте, репетиторов нет). Пустое состояние без упоминания фильтров.

### 7.6. Правила и ограничения

1. Каталог доступен авторизованному ученику независимо от статуса поиска и наличия анкет.
2. **Состав карточки репетитора** `[черновик до закрытия №23]`: ФИО, аватар, преподаваемые предметы (до 3, далее «+N»), цена за занятие, средний рейтинг, количество отзывов, город, формат занятий, значок «квалификация подтверждена», первая строка «о себе» (~80 символов). Контактные данные (email, телефон) не показываются — связь только через переписку.
3. **Логика матчинга с анкетой** (применима и к предустановке фильтров, и к первичной подборке №15): предмет анкеты входит в предметы репетитора; цена репетитора попадает в диапазон бюджета анкеты с учётом **обеих границ** (№22); при «договорной» — ограничение по бюджету не применяется; формат совпадает; при офлайн — город репетитора совпадает с городом анкеты; репетитор преподаёт уровень ученика.
4. **Рейтинг = среднее арифметическое всех опубликованных отзывов**, рядом — количество отзывов. Отображение с одним знаком после запятой `[Предложение]`. Взвешивание, антифрод, пересчёт при удалении отзыва — v2.
5. **Репетиторы без отзывов:** рейтинг отображается как «—»; при применённом фильтре по рейтингу исключаются из выдачи; позиция в сортировках — `[№24, на согласовании]` (предложение: в конец списка при сортировке по рейтингу, нейтрально — в прочих).
6. По умолчанию показываются все активные репетиторы, включая без подтверждённой квалификации (фильтр — опциональный). Значок квалификации — только у подтверждённых. Механика подтверждения квалификации вводится сценарием модерации; до него фильтр работает по полю `verification_status` со значениями по умолчанию «неподтверждена».
7. В каталог попадают только репетиторы: учётная запись активна, профиль опубликован, не заблокирован. Статусы и механика публикации профиля вводятся в сценариях репетитора — до них критерий считается определённым на уровне формулировки «активен и опубликован».
8. Фильтры не сохраняются между сессиями в v1 `[Предложение]`.
9. Пер-анкетная память подправленных фильтров (если понадобится по №21) — хранится локально на клиенте, на сервер не выносится `[Предложение]`.

### 7.7. Изменения модели данных

Обязательных изменений нет: фильтры — параметры запроса, состояние системы не меняется.

Предложения по `tutor_profiles` **(схема модуля репетиторов не предоставлена — сверить при получении)**:

- `avg_rating` (Numeric(2,1)), `reviews_count` (Integer) — денормализованные агрегаты, пересчитываются при публикации отзыва; финализируются в сценарии отзывов;
- `verification_status` — вводится сценарием проверки квалификации (модерация); фильтр 7.3 читает его;
- предметы, цена, формат, город, уровни репетитора — поля для матчинга, состав определяется в сценариях репетитора;
- индексы под типовые фильтры (предмет + цена; город + формат) — после сверки схемы `[Предложение]`.

Используемые справочники уже введены: `subjects`, `cities`, `education_levels`.
