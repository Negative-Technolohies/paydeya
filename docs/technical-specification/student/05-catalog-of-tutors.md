## 7. Поиск репетитора через каталог

### 7.1. Назначение

Процесс позволяет ученику самостоятельно подобрать репетитора в каталоге по параметрам и перейти к его профилю.

Граница разделов: здесь — фильтры, список карточек, их состав и стартовое состояние каталога. Просмотр полного профиля репетитора — отдельный сценарий (состав профиля определяется там). Начало переписки — сценарий переписки; самостоятельное сообщение ученика преподавателю описано в разделе 9.

### 7.2. Участники, пред- и постусловия

**Участник:** авторизованный ученик с активной учётной записью. Статус входящих предложений может быть любым — каталог доступен и при выключенном статусе (6.2, 6.6 п. 9), пресеты анкет при этом также доступны. Самостоятельный поиск ученика не гейтится этим статусом.

**Предусловия:** аккаунт активен. Доступ неавторизованных пользователей к каталогу — `[№25, на согласовании]`.

**Постусловия:** отсутствуют — раздел read-only, состояние системы не меняется. Аналитика просмотров/кликов — вне рамок v1 `[Предложение]`.

### 7.3. Входные данные

Фильтры поиска:

| Фильтр                      | Предустановка                           | Значения                                                                                                                |
| --------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Предмет                     | из активной анкеты `[№21]`              | выбор из `subjects`                                                                                                     |
| Цена                        | из бюджета активной анкеты `[№21]`      | диапазон «от–до», ₽ за занятие (60 мин); учитываются **обе границы** — цена репетитора должна попадать в диапазон (№22) |
| Рейтинг                     | нет                                     | минимальный порог из фиксированного набора: 4,0 / 4,5 / 4,8 `[Предложение]`                                             |
| Подтверждённые данные       | нет (выкл.)                             | вкл. — только репетиторы с одной или несколькими публичными отметками подтверждения                                      |
| Формат                      | из анкеты                               | онлайн / офлайн / любой                                                                                                 |
| Город                       | из анкеты (для офлайн)                  | выбор из `cities`                                                                                                       |
| Уровень образования         | из профиля ученика                      | выбор из `education_levels`                                                                                             |
| Сортировка                  | по умолчанию — «Рекомендованные»        | рекомендованные / рейтинг / цена ↑ / цена ↓ / количество отзывов / новые                                                |

Предустановки из анкеты применяются **только как стартовые значения формы** — ученик видит их и может изменить любое.

### 7.4. Основной процесс

1. Ученик открывает каталог преподавателей.
2. Сервер определяет активные анкеты ученика:
   - **активных анкет нет** — каталог открывается в режиме «Все преподаватели» без предустановок, с сортировкой «Рекомендованные»; показывается ненавязчивая подсказка «Создайте анкету — подберём репетиторов автоматически» `[Предложение]`; просмотр не блокируется;
   - **одна активная анкета** — фильтры предзаполняются её параметрами: предмет, бюджет, формат, город (для офлайн); уровень — из профиля;
   - **несколько активных анкет** — стартовым пресетом становится последняя активированная анкета; над каталогом показываются чипы активных анкет и режим «Все преподаватели». При выборе чипа анкеты её параметры подставляются в фильтры каталога; при выборе «Все преподаватели» анкетные фильтры сбрасываются.
3. Сервер формирует список: репетиторы в активном статусе с опубликованным профилем, прошедшие фильтры; выбранная сортировка; первая страница (20 карточек, подгрузка при прокрутке `[Предложение]`).
4. Ученик просматривает карточки. Состав карточки — 7.6, п. 2.
5. Ученик изменяет фильтры и применяет их (предложение: применение без кнопки, с задержкой на окончание ввода `[Предложение]`). Сервер перестраивает список; отображается количество найденных репетиторов.
6. Предустановленные фильтры сбрасываются кнопкой «Сбросить» или выбором режима «Все преподаватели» — возвращается общий каталог.
7. Ученик выбирает репетитора и открывает его профиль — дальнейшее описано в сценарии профиля репетитора. Из профиля «Написать» — сценарий начала общения учеником (раздел 9).

### 7.5. Ошибочные и альтернативные ветки

1. **Ничего не найдено.** Пустое состояние: «По вашим фильтрам ничего не найдено» + предложения ослабить бюджет, снять ограничение по городу/формату. Фильтры сохраняются, доступны к правке.
2. **Некорректные значения фильтра** (цена «от» > «до»). Ошибка по полю, список не перестраивается — остаётся прежний.
3. **Несколько активных анкет.** Ученик может переключаться между анкетами через чипы над каталогом или выбрать режим «Все преподаватели».
4. **Каталог пуст** (платформа на старте, репетиторов нет). Пустое состояние без упоминания фильтров.

### 7.6. Правила и ограничения

1. Каталог доступен авторизованному ученику независимо от статуса поиска и наличия анкет.
2. **Состав карточки репетитора:** ФИО, аватар, преподаваемые предметы (до 3, далее «+N»), цена за занятие, формат занятий, опыт, средний рейтинг, количество отзывов, город, наличие образовательных материалов, публичные отметки подтверждения (личность, образование, сертификаты — если есть), первая строка «о себе» (~80 символов). Контактные данные (email, телефон) не показываются — связь только через переписку.
3. **Логика матчинга с анкетой** (применима к предустановке фильтров и стартовому состоянию каталога №15): предмет анкеты входит в предметы репетитора; цена репетитора попадает в диапазон бюджета анкеты с учётом **обеих границ** (№22); при «договорной» — ограничение по бюджету не применяется; формат совпадает; при офлайн — город репетитора совпадает с городом анкеты; репетитор преподаёт уровень ученика.
4. **Рейтинг = среднее арифметическое всех опубликованных отзывов**, рядом — количество отзывов. Отображение с одним знаком после запятой `[Предложение]`. Взвешивание, антифрод, пересчёт при удалении отзыва — v2.
5. **Сортировка по умолчанию — «Рекомендованные».** После применения фильтров система сортирует преподавателей по многофакторному скорингу: соответствие параметрам ученика, средний рейтинг, количество отзывов, подтверждённые данные, заполненность профиля, наличие материалов/видео, активность на платформе и свежесть активности. Точная формула — вне v1; подробности вынесены в `technical-only/recomendation-system.md`.
6. **Репетиторы без отзывов:** рейтинг отображается как «—»; при применённом фильтре по рейтингу исключаются из выдачи; при ручной сортировке по рейтингу показываются после преподавателей с рейтингом. В сортировке «Рекомендованные» они не отправляются автоматически в конец и могут подниматься за счёт других факторов.
7. По умолчанию показываются все активные репетиторы, включая без подтверждённых данных (фильтр — опциональный). Публичные отметки подтверждения показываются только при наличии активных записей верификации. Механика подтверждения вводится сценарием модерации.
8. В каталог попадают только репетиторы: учётная запись активна, профиль опубликован, не заблокирован. Статусы и механика публикации профиля вводятся в сценариях репетитора — до них критерий считается определённым на уровне формулировки «активен и опубликован».
9. Фильтры не сохраняются между сессиями в v1 `[Предложение]`.
10. Пер-анкетная память подправленных фильтров — хранится локально на клиенте, на сервер не выносится `[Предложение]`.

### 7.7. Изменения модели данных

Обязательных изменений нет: фильтры — параметры запроса, состояние системы не меняется.

Предложения по `tutor_profiles` **(схема модуля репетиторов не предоставлена — сверить при получении)**:

- `avg_rating` (Numeric(2,1)), `reviews_count` (Integer) — денормализованные агрегаты, пересчитываются при публикации отзыва; финализируются в сценарии отзывов;
- `verification_status` — вводится сценарием проверки квалификации (модерация); фильтр 7.3 читает его;
- предметы, цена, формат, город, уровни репетитора — поля для матчинга, состав определяется в сценариях репетитора;
- индексы под типовые фильтры (предмет + цена; город + формат) — после сверки схемы `[Предложение]`.

Используемые справочники уже введены: `subjects`, `cities`, `education_levels`.
