## 4. Заполнение профиля ученика

### 4.1. Назначение

Процесс сохраняет базовую информацию об ученике: кто он, где находится, как представлен на платформе.

Граница разделов: **профиль описывает самого ученика**, **анкета описывает задачу поиска** (предмет, цель, бюджет, формат — 5.3). Правила видимости данных другим ролям определены в 5.6 п. 4 — здесь только ссылки, чтобы правила видимости жили в одном месте.

### 4.2. Участники, пред- и постусловия

**Участник:** авторизованный ученик с активной учётной записью.

**Предусловия:** регистрация завершена, профиль ученика существует (создан при регистрации — 3.4, шаг 6).

**Постусловия (успех):**

- данные профиля сохранены, обязательные поля заполнены;
- баннер «заполните профиль» больше не показывается;
- указанный уровень образования используется анкетой и фильтрами репетиторов (5.3, 5.4).

### 4.3. Входные данные

| Поле                | Обязательность | Валидация                                                                                                                         |
| ------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| ФИО                 | да             | хранится в учётной записи, редактируется через форму профиля                                                                      |
| Уровень образования | да             | выбор из справочника `education_levels`                                                                                           |
| Город               | нет            | выбор из справочника `cities`; при отсутствии города офлайн-поиск для ученика невозможен (в офлайн-анкете город обязателен — 5.3) |
| Часовой пояс        | —              | определяется по выбранному городу (`cities.timezone`); ручного ввода нет                                                          |
| Аватар              | нет            | jpg/png/webp, до 5 МБ; проверка по содержимому файла, не по расширению; приводится к 512×512                                      |
| «О себе»            | нет            | до 500 символов, без разметки                                                                                                     |

Контактные данные (email, телефон) в форме профиля не редактируются и другим пользователям не показываются. Смена контакта — отдельный сценарий с повторным подтверждением; контактные данные не видны на платформе нигде (5.6 п. 4).

### 4.4. Основной процесс

1. Ученик из личного кабинета открывает «Мой профиль».
2. Система отображает форму с текущими значениями (ФИО из учётной записи (введено при регистрации)).
3. Ученик заполняет/изменяет поля. Введённые данные хранятся локально в приложении; на сервер ничего не уходит до явного нажатия «Сохранить».
4. Ученик нажимает «Сохранить».
5. Сервер валидирует данные согласно 4.3.
6. При ошибках валидации — ветка 4.5.1.
7. При успехе сервер сохраняет данные и фиксирует время изменения (`updated_at`).
8. Ученик видит обновлённый профиль и подтверждение сохранения.
9. Повторное редактирование выполняется тем же процессом.

### 4.5. Ошибочные и альтернативные ветки

**4.5.1. Ошибки валидации.** Ошибки показываются в форме по полям; введённые данные не теряются, локальный черновик сохраняется, сохранение не выполняется.

**4.5.2. Некорректный аватар** (формат, размер, повреждённый файл). Загрузка отклоняется с указанием причины; остальные поля формы не затрагиваются.

**4.5.3. Истекла сессия во время заполнения.** Пользователь проходит повторный вход; локальный черновик сохраняется, пользователь возвращается к заполнению `[Предложение, необязательно для v1]`.

**4.5.4. Одновременное редактирование с двух устройств.** Сохраняется последняя версия по времени сохранения; конфликт не блокируется — поля простые, цена ошибки низкая.

### 4.6. Правила и ограничения

1. Редактирование профиля доступно только владельцу.
2. Контактные данные не редактируются в форме профиля и не отображаются другим пользователям (5.6 п. 4).
3. Премодерации полей профиля нет; контроль — постмодерация по жалобам `[Открытый вопрос №9]`.
4. Аватар по умолчанию — стандартная заглушка без фото; загрузка необязательна (среди учеников несовершеннолетние — минимизируем давление к публикации изображений).
5. Город — только выбор из справочника; свободный ввод запрещён; значения по умолчанию нет.
6. Изменение уровня образования задним числом анкеты не трогает: анкеты всегда читают актуальный уровень из профиля (5.7). Смена города в профиле не меняет город уже созданных офлайн-анкет — у анкеты поле самостоятельное (5.3).
7. Частота правок профиля не ограничена — осознанное решение v1; мягкий лимит, отсекающий автотесты/парсеры, — кандидат на v2.

### 4.7. Изменения модели данных

Целевая структура `student_profiles` (правки к текущей схеме):

| Поле               | Тип                                              | Комментарий                                                                                                    |
| ------------------ | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| id                 | BigInteger, PK                                   |                                                                                                                |
| user_id            | BigInteger, FK → `users.id`, NOT NULL, UNIQUE    | один-к-одному                                                                                                  |
| education_level_id | BigInteger, FK → `education_levels.id`, NOT NULL | решение №6                                                                                                     |
| city_id            | BigInteger, FK → `cities.id`, NULL               | необязателен (№8)                                                                                              |
| about              | String(500), NULL                                |                                                                                                                |
| avatar_key         | String, NULL                                     | ссылка на объект в файловом хранилище; сам файл в БД не хранится                                               |
| is_searching       | Boolean, NOT NULL, default false                 | «Ищу репетитора»; включается автоматически при первой активации анкеты (5.6, п. 6), дальше управляется вручную |
| updated_at         | datetime, NOT NULL                               |                                                                                                                |

Удаляемые поля: `verified` (состояние подтверждения живёт на уровне `users` — решение раздела 3), `active_questionnaire_id` (несовместим с правилом «одна активная анкета на предмет» — 5.7), `city` (заменяется на `city_id`).

Справочник `education_levels` (id, name; `name` — уникален): начальная школа, средняя школа, старшая школа, студент/высшее. Названия финально уточняются; заполнение — миграцией. Справочник `cities` общий с анкетами (5.7).

### 4.8. Вопросы

**Закрытые:**

| №   | Вопрос                    | Решение                                                                                                                                                |
| --- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 6   | «Класс» ученика           | Уровень образования из справочника (начальная / средняя / старшая школа, студент/высшее); в профиле обязателен; анкета и фильтры читают его из профиля |
| 7   | Видимость профиля         | Репетитору видны ФИО и данные профиля/анкет (состав — 5.6 п. 4); аватар — только в переписке; контактные данные не видны нигде                         |
| 8   | Город                     | Справочник `cities` (название + тайм-зона); в профиле необязателен, в офлайн-анкете обязателен                                                         |
| 9   | Модерация профиля и анкет | Без премодерации на данном этапе, только постмодерация по жалобам                                                                                      |
| 10  | Устаревание класса        | Снят: уровни меняются редко, ручного изменения достаточно                                                                                              |
